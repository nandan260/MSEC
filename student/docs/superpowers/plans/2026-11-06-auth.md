# MSEC Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow sign-in only for people on the roster, using Google, email and password, or an email code. Students see only their own data, and teachers see only their assigned branch+semester classes.

**Architecture:** Flask (`student/backend`) issues and verifies HS256 JWTs. The student React/Capacitor app, the teacher app and the Node assistant all send and check the same token.

**Tech Stack:** Flask, SQLite, PyJWT, google-auth, requests, werkzeug scrypt, EmailJS REST, pytest; React 19, Vitest, Capacitor (`@capacitor/browser`, `@capacitor/app`, `@capacitor/preferences`); Node `node:crypto`.

**Spec:** `student/docs/superpowers/specs/2026-11-06-auth-design.md`. Every endpoint, value, limit and message is defined there. Copy them exactly.

## Global Constraints

- Only these routes are public:
  - `/api/auth/config`, `/api/auth/login`, `/api/auth/code/*`, `/api/auth/password/reset` and `/api/auth/google/*`;
  - `/api/profile/verify/<usn>`;
  - `/uploads/*`;
  - the static SPA routes.
- All other `/api/*` routes return 401 when the token is missing or invalid.
- OTP codes expire after 5 minutes and die after 5 wrong tries. Each email can request one every 60 seconds, and each IP 10 per hour.
- Password lockout: 5 failures per email in 15 minutes, and 30 per IP in 15 minutes.
- JWTs last 7 days, or 30 days with `remember`.
- The Google exchange code is single-use and expires after 60 seconds. The Google flow expires after 10 minutes.
- OTP codes, OAuth codes, tokens and secrets are never logged. The only exception is `AUTH_DEV_LOG_CODES=1` outside production.
- Every user lookup uses the lowercase email and must also pass `ALLOWED_EMAIL_DOMAINS`.
- The seeded data stays attached to user 1. Existing frontend screens must keep working for user 1.

## Review Focus

1. **Old databases.** The `users` rebuild must keep the rows, IDs and password hashes of an existing `student_portal.db`. Test: `migration preserves existing users`.
2. **Missed hardcoded IDs.** Any leftover `student_id = 1` or `LIMIT 1` profile read leaks Alex's data to other users. Test: `student B sees none of A's rows` covers the dashboard, assignments, attendance, academics, placements, events and fees.
3. **Concurrent code use.** Two verify requests with the same OTP code must not both succeed. Test: `otp single use under double submit`.
4. **APK return.** `msecstudent://auth-return` is caught while the app is running and also on a cold start. Test: `handles appUrlOpen and launch url`.
5. **Expired token mid-session.** The app returns to sign-in and comes back to the same screen without losing it. Test: `401 redirects and returns to screen`.
